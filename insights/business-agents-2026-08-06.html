二、单据 Agent 深度拆解

1. 文档解读层：已发生范式转移

  • 传统OCR（PaddleOCR ⭐87k）：依赖版面分析，适合规整文档
  • 免OCR视觉理解（Donut、LayoutLMv3）：图像直接生成结构化文本，适合固定版式票据，泛化弱
  • 视觉LLM端到端（当前主流）：泛化极强，但有幻觉+坐标丢失风险
✅ 实战最优解 = 「VLM 粗抽 + 传统 OCR 坐标校准」混合模式

2. 表格/版式理解：深水区

开源 CascadeTabNet(⭐1550)、TableStructureRec(⭐960) 解决基础结构；MinerU(⭐76.9k) 复杂 PDF 转 Markdown 表现优异；商业级 TextIn xParse 长文档/复杂表格更优，附带证据链追溯。

3. 数据匹配层：真正的核心难点

提取字段与作业系统上百字段宽表的映射不能靠字面匹配，需构建 Semantic Layer。金额用单位换算容差、单据号用正则+编辑距离模糊匹配，再通过业务含义API二次校验。

4. 真实性检测层：最残酷的真相区 🔴

  • PS篡改检测：开源有 Tampering-Detection（ELA/噪声分析）、商业有 TextIn 通用篡改检测——可解决基础伪造
  • 印章真伪检测：开源界几乎空白。涉及物理防伪+印油分析+强法律属性，业界成熟方案全是商业私有化或对接公安/工商权威备案接口
⛔ 不要用纯开源 CV 模型自研印章真伪——那是法律与审计责任的重灾区

5. 开源选型建议

主打 MinerU（综合最强）或 Docling（IBM）；底层OCR兜底 PaddleOCR；复杂表格+防伪要求高 → 直接采购 TextIn。

三、合规 Agent 深度拆解

1. 两条路线取舍

  • ❌ 纯 LLM+RAG：有致命幻觉，无法满足确定性
  • ❌ 纯规则引擎（gorules/zen ⭐1872）：维护成本高，看不懂模糊制度
  • ✅ Neuro-symbolic 混合：LLM读制度→编译成DSL/JSON规则→交规则引擎执行→LLM只做结果解释与异常路由

2. 规则抽取难点

制度多为模糊表述（"重大金额需高管审批"），难点在实体对齐+阈值量化。需结合业务知识库把"重大金额"映射到宽表API的具体字段和数值，高度依赖人工Review。

3. 数据校验 + 可解释（合规命门）

必须输出证据链：引用制度原文第X条 + 关联API字段Y + 实际值Z。LLM 不能黑盒判断，须输出结构化推理日志。

4. 与业务语义层耦合 🔗

合规校验高度依赖"高业务含义API"。需用语义层（如 OpenSPG/KAG ⭐8.9k）保证制度概念与API字段在同一语义空间，避免"查数"与"校验"口径割裂。

四、两大领域共性底座（关键洞察）💡

单据Agent = 把非结构化文档降维成结构化数据
合规Agent = 把结构化数据与半结构化制度对齐

两者都需要统一 Semantic Gateway（语义网关）：向下对接解析结果（MinerU/TextIn）和宽表API，向上支撑Agent推理。

团队正在研究的"业务知识库/语义层"，正是这个底座的核心——不但是查数字典，更是单据映射的锚点、合规校验的标尺。

五、落地路线与风险

分阶段建议

  • MVP：单据Agent先做"PDF/Excel解析+宽表API录入"，暂避印章真伪（改人工复核/权威接口）；合规Agent先做"制度RAG问答+简单确定性规则校验"
  • 进阶：引入VLM提升单据泛化，构建Neuro-symbolic合规引擎，半自动编译制度→规则

技术风险清单

  • VLM幻觉：密集表格易行列错位→财务数据录错，必须OCR坐标交叉验证
  • 法律风险：自研印章检测误判（假章认真）→审计事故，AI只能辅助定位
  • 伪合规风险：合规Agent过度依赖LLM直出结论→"看似合理实则违规"，必须规则引擎兜底

六、一句话结论

🎯 放弃用大模型包打天下的幻想。用 VLM 解决单据泛化，用规则引擎死守合规底线，把团队核心精力倾注于连接文档与宽表 API 的"业务语义层"建设——这才是企业级 AI Agent 真正的护城河。 —— 由 qwen3.7-max 强力模型系统分析提炼
