ERF-SQL: 企业 Text-to-SQL 部署就绪框架——Benchmark 精度≠部署安全

2026-08-27 · IJARCCE (via OpenAlex)
企业试点 LLM text-to-SQL 反复发现同一问题：在 Spider 上达 85% execution accuracy 的模型仍会被安全审查/审计/风险委员会拒绝。post-mortem 中生成的查询忽略行级访问策略、暴露脱敏列、在 schema 变更下静默失败、运行无界扫描、不留审计轨迹。ERF-SQL 提出版本化语义契约（versioned semantic contract）作为 schema 与 model 间唯一接口，Policy-Aware Query Guard 在执行前重写候选查询的 AST 以强制策略，不确定答案路由至澄清或人工审查，行为按六维就绪指数评分。在 EntSQL-450 上，四个生产 LLM 在真实角色策略下损失 19-23 个精度点，ERF 恢复 13-16 点，拦截 97% 不安全生成，drift resilience 从 0.55 升至 0.86，延迟增加约 0.9s/查询。
🔍 技术视角：这篇论文用硬数据证明了 8/26 Beyond the Harness 的'benchmark 精度≠真实业务系统效果'论断——Spider 85% 在 EntSQL-450 上直接掉 19-23 点。ERF-SQL 的核心贡献是把'deployment readiness'从'希望'变成'可工程化可测量'：版本化语义契约=schema 唯一接口（与 Cube/WrenAI 的 semantic layer 定义同构），Policy-Aware Query Guard=执行前确定性 AST 重写（与 8/19 Policy Algebra path property + 8/22 SBproxy Cedar 策略引擎共振）。六维就绪指数+gated Enterprise Readiness Index 为用户提供了评估 Agent 查数可信度的框架。对用户'不直连数据库、通过业务 API 查数'场景，Policy-Aware Query Guard 的 AST 重写思路可直接迁移为'API 调用前参数级策略校验'。

Vector RAG vs Graph RAG 基准：Graph RAG 在可信度三维领先，架构选择应任务驱动

2026-08-27 · Journal of Information Technology in Construction (via OpenAlex)
本文在英国政府重大项目组合（GMPP）2020-2024 数据集上基准对比两种 RAG 架构：Vector hybrid pipeline（metadata filtering+dense retrieval+BM25 re-ranker）vs Graph RAG pipeline（labelled property graph+schema-aware retrieval），固定 GPT-4.0 模型/prompt/生成设置以隔离检索架构效果。Graph RAG 在 faithfulness（0.81 vs 0.78）、context recall（0.87 vs 0.83）、answer relevancy（0.74 vs 0.69）三维领先，Vector RAG 在延迟和 token 消耗更低+context precision 略高（0.86 vs 0.85）。专家盲评也认为 Graph RAG 在 accuracy/completeness/trustworthiness 更高，但偏好因查询类型而异。结论：架构选择应由预期查询类型、信息风险、效率/provenance/决策支持可靠性相对重要性驱动。
🔍 技术视角：这是对用户'语义层 vs 知识图谱'双路线最直接的实证对比——不是理论讨论而是真实政府项目数据上的 RAGAS+专家盲评。Graph RAG 在 faithfulness/context recall/answer relevancy 三维领先直接回答了'知识图谱路线在哪些场景优于语义层'：当查询需要跨实体关系推理和完整 provenance 时。但 Vector RAG 在延迟/token 消耗上更低——对用户上百字段宽表 API 场景，如果查询主要是单表字段查找则 Vector 足够，如果需要跨表关系推理则 Graph 更优。这与 8/20 TDS Kimi K3 实测'语义层补 completeness 非 grounding'共振：Graph RAG 的 context recall 0.87 vs 0.83 正是 completeness 优势。

GRID: 语法约束解码引擎——将 RBAC 编译进文法，4 项形式化保证+hash-chained 审计

2026-07-11 · arXiv (via Semantic Scholar)
GRID（Grammar-Railed Decoding）提出语法约束解码引擎，key 基于 parser 配置（lexer scan state × LALR(1) stack）而非 token 序列，用增量推进的 LALR(1) parser 本身作为 viable-prefix oracle。LLM token 通过 byte-level trie walk 桥接到文法 terminal，context-independent/dependent split 使 cache-key soundness by construction。角色访问控制编译进语言：role projections 子集化文法 productions，schema lexicons 限制 identifier terminals，使禁用动词和标识符在 mask 层级不可达。四项保证（soundness/completeness/termination/near-constant per-token cost）各有明确前置条件+测试。Rust kernel 实现 3.6-6.7μs 中位 per-token mask，在 p50/p90 领先 llguidance，n=16000 位置平坦。Spider 上 +13 execution accuracy（0.5B），7B+一轮 checker-guided repair 达 94.5% executable。hash-chained per-token 审计轨迹 100% 篡改检测。
🔍 技术视角：GRID 把安全治理从'自然语言请求'推进到'文法编译'——禁用动词不是提示词说'不要做'而是 mask 层级物理不可达。这与 8/26 'Do Not' Is Not Deny（481 个 CLAUDE.md 安全规则 4-16% 有匹配控制）形成最强对比：CLAUDE.md 靠模型遵从（不可保证），GRID 靠文法约束（物理保证）。对用户上百字段宽表 API 场景，GRID 的 role projections 子集化文法思路可迁移为'按角色子集化 API 字段集'——字段级 RBAC 在生成层不可达而非运行时过滤。四项形式化保证（soundness/completeness/termination/near-constant cost）为生产部署提供可审计的数学基础。hash-chained 审计轨迹与 8/19 Quipu 审计即查询共振。

📊 架构示意

🎯 为什么值得关注

GRID 是'安全治理代码化'路线的最极端实现——不是在查询生成后过滤（post-hoc），不是在提示词中请求（advisory），而是在解码时 mask（enforcement by construction）。对用户'字段级权限治理'需求，GRID 提供了'禁用字段在生成层物理不可达'的工程路径。4 项形式化保证+hash-chained 审计是风控/审计委员会可接受的部署标准。

⚙️ 核心机制

核心技术：(1) Grammar-constrained decoding——next-token mask key=parser 配置（lexer scan state × LALR(1) stack），用 parser 自身作 viable-prefix oracle；(2) Byte-level trie walk——LLM token→grammar terminal 桥接，context-independent/dependent split 保证 cache-key soundness；(3) RBAC 编译进文法——role projections 子集化 productions，schema lexicons 限制 identifier terminals，禁用项 mask 层不可达；(4) 4 保证——soundness（不生成非法 token）/completeness（不拒绝合法 token）/termination（parser 终止）/near-constant per-token cost（位置平坦）；(5) hash-chained audit——per-token 审计轨迹 bit-identical replay+100% tamper detection。

🛠️ 落地建议
