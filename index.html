EvoSafeHarness：按模型+域进化的安全 Harness 优化框架

2026-09-12 · HuggingFace Papers (arXiv 2609.05903)
UC Berkeley/CMU 团队（Li/Ma/Cao/Suh/Bo Li/Dawn Song/Chaowei Xiao）提出 EvoSafeHarness：安全 harness 不再是专家一次性设计后通用部署，而是针对冻结模型在目标域中联合搜索自然语言策略+可执行代码逻辑，由模型行为、域规范、fresh-context 对抗审查引导。fresh-context 对抗审查专门拒绝 benchmark-specific 规则（防过拟合到测试集）。在 4 个 agent benchmark 基准族上，EvoSafeHarness 的安全-效用前沿优于固定专家设计的 harness。harness 严格度因模型而异——一个模型需要更多 enforcement 才会效用下降，跨域策略可能遗漏应用特定安全关系。
🔍 技术视角：对用户"业务 Agent 安全治理"方向是范式级信号：用户通过 API 调数不直连数据库，安全 harness 是 agent 调用业务 API 的 enforcement layer。EvoSafeHarness 证明"写一次 CLAUDE.md 安全规则"不够——不同模型需要不同严格度，不同业务域有不同的状态/动作序列/效果需治理。用户上百字段宽表 API 场景下，哪些字段可查/不可查/需脱敏是 deployment-dependent 的。建议把内部 agent 安全治理从"写一次规则"升级为"按模型+域联合优化可进化 harness"，特别是 fresh-context 对抗审查拒绝 benchmark-specific 规则的方法论可直接迁移——防止安全规则过拟合到内部评测集。

Procedural Graphs：过程知识图化为自演化执行结构

2026-09-12 · HuggingFace Papers (arXiv 2609.09153)
Google 团队（Lu/Chen/Wu/Arık）提出 Procedural Graph：把过程知识从隐式 prompt 历史中显式化为 (procedure, relation, procedure) 三元组——类似知识图谱用 (entity, relation, entity) 组织事实知识，但 Procedural Graph 组织"做什么/什么顺序/什么条件"的过程知识。每步决策时定位 agent 的 active node，guidance model 把周围子图翻译为步骤级情境引导，bias solver 的下一步动作但不 dictating。图自演化：LLM refiner 对比失败/成功轨迹编辑图拓扑和属性，保留提升 held-out 验证性能的编辑、保留被拒编辑以防回归。
🔍 技术视角：对用户"上百字段宽表 API 多步调用"方向是直接可迁移的结构：业务 Agent 调多个 API 完成一个业务分析任务，调用顺序和条件依赖是过程知识——目前隐式在 prompt 历史中，随轨迹变长 agent 会失序/重复/跳步。Procedural Graph 把这些过程知识显式化为可查询图，active node 定位+guidance 翻译=给 agent 步骤级引导而非自由生成。自演化机制（对比失败/成功编辑图拓扑）意味着图能从真实 API 调用轨迹中学习——这与用户已有的 API 调用日志直接对接。建议把业务 API 调用流程从 prompt 描述升级为 Procedural Graph 表示。

LLM 交易 Agent 生产数据：运营层决定行为远超策略文本

2026-09-12 · HuggingFace Papers (arXiv 2609.05663)
Barton 等人（DX Terminal）发布 6 个月生产级测量记录：DX Terminal Pro（3,505 个用户资金金库交易真实 ETH）+ DXAP alpha fleet（500-599 个用户创建 agent，91-117 并发活跃，交易 Hyperliquid perps）。7.5M 单模型调用+~300K 链上操作+231,638 多工具轮次产出 14,596 笔成交。四个发现：1.运营层决定行为远超策略文本——风险滑块解释杠杆(+0.425/level)，agent 固定效应吸收 60% 方差，leaderboard 渲染边界因果路由选择(1.75x)。2.仓位 sizing 对波动盲——中位杠杆 5.0x 在每个波动分位相同，11% 的书占 62% 清算。3.agent 几乎不捕获其触及的上行——43.2% 仓位至少经历一次清算。4.生产中 agent 行为由运营层（滑块/UI/排行榜渲染边界）决定而非策略文本。
🔍 技术视角：对用户"业务 Agent 立项决策"方向是最硬的警示数据：agent 生产行为主要由运营层（UI 控件/渲染边界/排行榜）决定而非策略文本（prompt 里写的策略）。这意味着用户在业务 Agent 中写的"查询策略"prompt 可能远不如 API 接口的字段暴露方式/查询参数默认值/结果展示方式对 agent 行为影响大。用户上百字段宽表 API 场景下，哪些字段排在前面/默认值是什么/返回多少行——这些"运营层"设计可能比 prompt 里的"查询策略"更决定 agent 实际行为。

💼 商业启示
