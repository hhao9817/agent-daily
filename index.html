SCAIR: Schema-Conditioned Agentic Iterative Reasoning for Enterprise Knowledge Graphs

2026-06-02 · arXiv 2607.22571
面向企业知识图谱的 Schema 条件化 Agent 迭代推理框架。它让 agent 先理解图 schema，再在 KG 上做迭代推理，以回答问题。核心是解决企业图谱中'语义稠密但结构复杂'的查询问题。
🔍 技术视角：这正是你课题第 1、2 环的结合点：把业务对象关系（schema）作为 agent 的推理前提，而不是让 agent 盲目检索。对做业务知识库的团队，'schema 条件化'是让 AI 真正懂业务关系的关键设计，强烈建议精读。

2026-07-24 · arXiv 2607.22319
讨论从朴素 RAG 走向 Agentic RAG 的数据集成路线，强调在保证结果可信（trustworthy）的同时控制成本（cost-efficient），覆盖多源业务数据接入与整合。
🔍 技术视角：业务数据查询最大的痛点就是'多源异构 + 可信度'。这篇文章的 Agentic RAG 思路（把检索变成由 agent 主导的规划执行）比你现在的朴素方法更能应对复杂业务查询，值得对照你的知识库架构评估。

基于 GraphRAG 的语义数据分析方法，把业务数据的语义关系组织成语义图，再用 RAG 支撑分析问答。强调语义层面的可解释分析。
🔍 技术视角：GraphRAG 是构建业务知识库的热门路线。它把'业务对象之间的语义关系'显式建模成图，比纯向量检索更能支撑'懂业务上下文'的分析。可作为你知识库技术选型的候选。

AttnLink: Turning Attention into Schema Links for Text-to-SQL

2026-08-01 · arXiv 2608.00693
把 LLM 的注意力机制转化为 text-to-SQL 的 schema linking 信号，提升复杂业务表结构下 SQL 生成时对 schema 的准确对齐。
🔍 技术视角：schema linking 是企业级 text-to-SQL 准确率的最大瓶颈（业务库 schema 往往几百上千张表）。这篇的角度（用注意力做关联）值得了解，属于'精确查询'环节的前沿技术。
